# AGENT.md — как работать с этим проектом

> **Входная точка** для любой сессии/агента/инструмента, работающего с репозиторием.
> Прочитай этот файл первым, затем [`checklist.md`](docs/checklist.md) и [`decisions.md`](docs/decisions.md).

---

## Что это за проект

**Персональный помощник инвестора/трейдера по крипторынку.** Еженедельный
исследовательский дайджест: evidence-first, анти-повтор с памятью, on-chain-
подтверждение, whale-активность, инвестиционная интерпретация.

6-фазный конвейер, верификационная цепочка, SQLite-память, локальный bge-m3,
сменный LLM-шлюз.

---

## Текущий статус

**Фазы: M0–M6 завершены.** Полный конвейер на 10 зонах (RSS + fetch_url + поиск →
bge-m3 → отбор → кластеризация → agentic loop → верификация → интерпретация + whale +
календарь → Markdown/DOCX), фоновый запуск `POST /runs`, eval/метрики, мониторинг,
документация, интерактивный дашборд (Plotly). Все гейты — см.
[`checklist.md`](docs/checklist.md).

## Принятые инварианты (НЕ менять без явного согласования)

- Это **исследовательские сигналы, а не индивидуальные инвестиционные рекомендации**.
  Запрещено: «покупай/продавай», ценовые таргеты, гарантии доходности.
- Формат — **еженедельный дайджест** (не real-time алерты).
- Покрытие — **RU + EN**.
- Унаследованные принципы: **evidence-first, анти-повтор с памятью, цитирование по
  номеру каталога `[Ист](N)`, честная дата, fail-closed/fail-open**.
- Зоны и источники — **конфиг (`config/`), а не код**.
- Порядок разработки — **по фазам M0 → M4** из `plan.md`; не прыгать вперёд, пока
  не закрыты блокеры фазы.

## Как мы отслеживаем изменения (single source of truth)

- **`checklist.md`** — *текущее состояние*: что открыто/закрыто (checkbox-ы) + гейты фаз.
- **`decisions.md`** — *журнал*: у каждого вопроса (D-xx — решение, F-xx — факт-чек)
  есть «Рекомендация», «Статус», «Решение», «Дата».
- **`requirements.md` / `plan.md`** — спецификации; меняются только через принятое
  решение в `decisions.md`, а не напрямую.

ID (`D-01`…`D-10`, `F-01`…`F-02`) — **сквозные** между `decisions.md` и `checklist.md`,
чтобы они не рассинхронизировались.

## Протокол сессии

### Начало сессии
1. Прочитать этот файл.
2. Прочитать [`checklist.md`](docs/checklist.md) — что открыто.
3. Прочитать [`decisions.md`](docs/decisions.md) — что уже решено.
4. Определить задачу сессии; если она требует незакрытое решение — сначала закрыть его.

### Конец сессии (обязательно, чтобы не теряться)
1. Принятые решения зафиксировать в `decisions.md`: статус `✅`, «Решение», «Дата».
2. Отметить `[x]` в `checklist.md`.
3. Обновить `plan.md` / `requirements.md` **только если меняется скоуп** (и только
   через запись в `decisions.md`).
4. Кратко записать прогресс/следующий шаг (в `decisions.md` или отдельным логом).

## Язык и соглашения

- Документы и комментарии — **на русском**; код и идентификаторы — **на английском**.
- Статусы в `decisions.md`: `🔲` открыт · `✅` решён · `⏸️` отложен (не блокер MVP).
- Не начинать код фазы, пока не закрыты её блокеры (см. `checklist.md`).
