### D-14. Память на 18 ГБ (M1): модели не резидентны одновременно
- **Блокирует:** M1 (фазы embed/cluster)
- **Рекомендация:** bge-m3 — в сабпроцессе с выходом; Ollama — `OLLAMA_KEEP_ALIVE=1m`; одна модель за раз; fallback `qwen3:8b`
- **Статус:** ✅
- **Решение:**
  1. Правило: в один момент — не более одной тяжёлой модели (`qwen3:14b` ~9 ГБ в Ollama ИЛИ `bge-m3` ~2–3 ГБ в Python), никогда одновременно.
  2. Порядок фаз: collect (без моделей) → embed (bge-m3) → filter (SQLite) → cluster (qwen) → report.
  3. bge-m3 считать в отдельном процессе, который грузит модель, пишет эмбеддинги в SQLite и выходит (гарантированный возврат памяти ОС; надёжнее `del`+`gc` из-за аллокатора torch/MPS).
  4. Ollama: `OLLAMA_KEEP_ALIVE=1m` (или `ollama stop qwen3:14b` после LLM-фаз), чтобы qwen не висел резидентом.
  5. Fallback при жёлтой/красной зоне `memory_pressure -Q` → `qwen3:8b` (~5 ГБ).
- **Дата:** 2026-10-20

### D-24. Цели метрик (precision/recall)

### D-25. Фоновый запуск `POST /runs`
- **Блокирует:** M4
- **Рекомендация:** FastAPI `BackgroundTasks` (один пользователь — очередь не нужна)
- **Статус:** ✅
- **Решение:** `POST /runs` создаёт запись прогона (`status=running`) и возвращает `run_id` сразу; конвейер исполняется в `BackgroundTasks` с отдельным `SqliteRepository` (изоляция соединения SQLite). `GET /runs/{id}` — поллинг статуса. CLI `run` остаётся синхронным.
- **Дата:** 2026-10-21

### D-26. Ретроспективный false-positive: правило классификации
- **Блокирует:** M4 (пост-M4)
- **Рекомендация:** через 2–4 недели сравнить текущую цену pump-флага с ценой первого сигнала
- **Статус:** ✅
- **Решение:** Для трендов с pump-флагом (D-08) сравнение первой цены (`onchain_observations.metric='price'`) и текущей: текущая ≥ первой → «тренд» (цена закрепилась, ложный pump-флаг); текущая < первой → «памп» (ложный тренд). Инструмент `retro` (CLI) реализован; прогон по реальным данным — после накопления 2–4 недель истории.
- **Дата:** 2026-10-21

### D-27. Калибровка порогов — конфигурируемо, не код
- **Блокирует:** M4 (пост-M4)
- **Рекомендация:** вынести пороги анти-повтора и pump-фильтра в `config.py`
- **Статус:** ✅
- **Решение:** Пороги `anti_repeat_threshold` (0.85), `pump_price_change_7d` (30.0), `confirmation_change` (10.0) вынесены в `config.py` и прокидываются в `Verifier` через `VerifyThresholds`. Калибровка по eval = изменение конфига, без правок кода.
- **Дата:** 2026-10-21

- **Блокирует:** M6
