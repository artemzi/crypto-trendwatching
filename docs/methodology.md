# Методика: как формируется дайджест и как принимаются решения

> **Назначение:** объяснить «почему так», а не только «как». Каждый порог и правило
> имеет ссылку на ID решения (`D-xx`/`F-xx`) из [decisions.md](./decisions.md).
> Читать после [architecture.md](./architecture.md), если нужны детали устройства.

---

## 1. Зачем система

Персональный еженедельный **исследовательский** дайджест по крипторынку. Ключевая
позиция: это **сигналы для самостоятельного анализа, а не инвестиционные
рекомендации**. Система сознательно не даёт «покупай/продавай», ценовых таргетов и
гарантий доходности (инвариант, [AGENT.md](../AGENT.md)).

Три принципа, унаследованные от эталонного решения Trendwatching:

1. **Evidence-first** — каждый тренд подкреплён живой ссылкой и цитатой, а не
   утверждением модели.
2. **Анти-повтор с памятью** — уже замеченное не переоткрывается заново.
3. **Честная дата и цитирование** — источник цитируется по номеру каталога
   `[Ист](N)`, URL подставляет код (модель не может выдумать ссылку).

---

## 2. Конвейер: 6 фаз прогона

Один прогон по зоне проходит фиксированный набор фаз (реализация —
`application/pipeline.py`):

| # | Фаза | Что делает | Порог/правило |
|---|------|-----------|----------------|
| 1 | **collect** | RSS + `fetch_url` + поиск (Яндекс) собирают сигналы; параллельно whale-сбор | whale ≥ $1M (D-05) |
| 2 | **filter** | эмбеддинги bge-m3; дедупликация URL; отбор по косинусу к профилю зоны | cosine ≥ 0.3 (D-07) |
| 3 | **cluster** | LLM группирует сигналы в тренды-кандидаты (чанки по 40, ретрай) | зрелость D-06 |
| 4 | **research** | agentic loop: LLM вызывает инструменты `fetch_url`/`search_web`/`check_onchain` | — |
| 5 | **verify** | верификационная цепочка (см. §3) | см. §3 |
| 6 | **report** | обогащение (whale-маппинг, интерпретация, катализаторы) + Markdown/DOCX | D-04, D-08 |

Прогон **синхронный** в CLI (`run`) и **фоновый** в веб-UI (`POST /runs` через
`BackgroundTasks`, D-25). Стоимость и латентность фаз фиксируются в `funnel_json`
(мониторинг, NFR-1…NFR-3).

---

## 3. Верификационная цепочка

Каждый тренд-кандидат проходит цепочку проверок (`application/verify.py`). Цепочка
пишет `evidence_bindings` (цитата ↔ источник) и `evidence_verdicts` (вердикты,
append-only).

1. **Живость ссылки** — HEAD/GET по URL; недоступный URL → вердикт `dead`.
2. **Анти-повтор (novelty-gate)** — косинус эмбеддинга `name + definition` против
   `reported_trends.embedding`; порог **0.85** (D-17). Совпадение → тренд отклоняется
   как «ранее замечено».
3. **Релевантность цитаты** — LLM-судья: подтверждает ли цитата тезис
   (`relevant`/`irrelevant`/`unknown`).
4. **Обоснованность** — LLM-судья: обоснован ли тезис собранными доказательствами
   (`sound`/`unsound`/`unknown`).
5. **Pump-фильтр (D-08)** — если цена выросла ≥ **+30% за 7 дней**, а TVL/объёмы
   выросли < **+10%** (или данных нет) → флаг «нарратив без on-chain-подтверждения».

Прошедший кандидат запоминается в `reported_trends` (память анти-повтора) и получает
freshness-снимок в `trend_velocity` (цена/TVL, дельта first→last, D-22).

## 4. Пороги и почему они такие

| Порог | Значение | Решение | Почему |
|-------|---------|---------|--------|
| Отбор сигналов по зоне (косинус) | 0.3 | D-07 | баланс полнота/шум на старте |
| Зрелость тренда | зарождающийся/растущий/устоявшийся/угасающий | D-06 | крипто-адаптация классической шкалы |
| On-chain «подтверждение» | TVL/объём ≥ +10% за 7д | D-07 | тренд подтверждён деньгами |
| Pump-фильтр | цена ≥ +30% за 7д при TVL/объём < +10% | D-08 | «нарратив без подтверждения» |
| Whale (крупный трансфер) | ≥ $1M | D-05 | операционное определение «кита» |
| Анти-повтор (косинус) | 0.85 | D-17 | старт; калибруется по eval (D-27) |
| Катализаторы | unlock/governance/upgrade/regulatory/macro | D-21 | DefiLlama unlocks + LLM-экстракт |

Пороги `anti_repeat_threshold`, `pump_price_change_7d`, `confirmation_change`
**конфигурируемы** через `.env` (`config.py` → `VerifyThresholds`, D-27) — калибровка
по eval не требует правок кода.

## 5. Agentic loop (исследование)

Фаза `research` (`agent/`): LLM получает кандидата + его сигналы и может вызывать
инструменты до N раундов, затем даёт итоговые заметки.

- Инструменты: `fetch_url` (текст страницы), `search_web` (поиск), `check_onchain`
  (TVL/объём/цена).
- Tool-calling: **нативный function calling** для DeepSeek (OpenAI-совместимый),
  **ReAct-JSON** для Ollama (D-19).
- **URL подставляет код** — доказательства собираются из фактически вызванных
  инструментов, модель не может выдумать ссылку.

---

## 6. Цитирование по каталогу

- Каталог источников строится **один раз на прогон** из порядка `config/sources.yaml`
  (`source_id → N`, D-16) и кладётся в `funnel_json`.
- В отчёте ссылка пишется как `[Ист](N)`; в секции «Источники» номеру сопоставлены
  имя и URL. URL подставляется кодом — не из вывода модели.

---

## 7. Интерпретация и whale-маппинг

- **Интерпретация (D-04)** — блок на тренд: направление нарратива
  (бычий/нейтральный/медвежий), горизонт (недели/месяцы/кварталы), 3–5 катализаторов,
  3–5 risk-флагов, статус on-chain (подтверждено/нейтрально/расходится) и **обязательный
  дисклеймер**.
- **Whale-маппинг (FR-6)** — LLM сопоставляет whale-трансферы (актив/сумма/субъекты) с
  трендом → «подтверждение/расхождение/нейтрально». **Инвариант:** никогда не
  «сигнал повторить сделку».

---

## 8. Fail-open / fail-closed

- **Fail-open** (не роняем прогон): коллекторы, поиск, on-chain, whale при ошибке
  возвращают пустой результат/`None`; ошибка одной зоны не убивает `--all`;
  circuit breaker (`application/circuit_breaker.py`) после N подряд ошибок временно
  отключает провайдера.
- **Fail-closed** (не выдаём недостоверное): анти-повтор отклоняет дубли; тренд без
  живой ссылки помечается; дисклеймер — в отчёте, веб-UI и DOCX (NFR-5).

---

## 9. Ограничения и не-цели

- **Не инвестиционная рекомендация** — исследовательские сигналы для самостоятельного
  анализа; без ценовых таргетов и гарантий (инвариант).
- Покрытие источников неполное: X/Twitter исключён (D-10); DefiLlama unlocks может быть
  недоступен → катализаторы честно помечаются неполными (D-21).
- Whale-обогащение активно только при ключе `WHALE_ALERT_API_KEY`; без него — «нет
  данных» (D-20).
- Ретроспективный false-positive (памп vs тренд) требует 2–4 недель истории (D-26);
  eval-сет наполняется из реальных отчётов (D-23).
- Формат — еженедельный дайджест, не real-time алерты.

## 10. Как читать дайджест

Структура отчёта — 8 секций (см. [usage.md](./usage.md), §«Чтение дайджеста» и
`requirements.md` §9): резюме недели, тренды с интерпретацией, развитие ранее
замеченных, слабые сигналы, whale-активность, катализаторы, источники, воронка +
отклонённые повторы.
