# M0 — оценка готовности и правки перед стартом разработки

> **Статус:** готово к исполнению (правки, не пересборка)
> **Дата:** 2026-10-20
> **Связанные:** `plan-m0.md`, `plan.md`, `requirements.md`, `decisions.md`, `checklist.md`, `config/sources.yaml`, `config/topics.yaml`

## Вывод оценки

`plan-m0.md` пригоден к исполнению. Глобальная переработка не требуется. Перед стартом
M0 нужно применить два точечных дополнения и одну синхронизацию документов. Все решения
D-01…D-11 закрыты, F-01 закрыт; F-02 (бюджет) корректно остаётся открытым и блокирует M1,
а не M0 (M0 гоняет stub-LLM без реального прогона).

## Что исправить до старта M0

### 1. Добавить реальные RSS-адреса (блокер)

`sources.yaml`: у источников с `method: rss` поле `url` содержит домашнюю страницу, а не
фид. `feedparser` не соберёт фид с главной страницы.

- Ввести поле `feed_url` для всех `rss`-источников (медиа EN/RU, `cbr`).
- Для источников без стабильного RSS (`coindesk`, `cointelegraph`, `incrypted`) — либо
  проставить известный feed-адрес, либо сменить `method` на `fetch_url`, чтобы M0 их не
  пытался собрать через feedparser.
- `url` оставить как есть (для citation/ссылок).

### 2. Маппинг «зона → источники» для M0 (решено)

**Решение:** для M0 `RssCollector.collect(zone)` собирает **все включённые (`enabled: true`)
`rss`-источники** независимо от категории и помечает их `zone_id` текущего прогона.
Семантическая фильтрация по зоне остаётся на M1 (эмбеддинги bge-m3). Поле `zones` в
`sources.yaml` на M0 не вводим.

Следствия для `plan-m0.md`:
- Шаг 6: уточнить, что `RssCollector` берёт фиды из всех enabled `rss`-источников.
- Протокол `SourceCollector.collect(zone) -> list[Signal]` оставить без изменений — `zone`
  используется как метка `zone_id` в M0.

### 3. Синхронизация документов (не блокер M0, сделать вместе с правками)

- `requirements.md` §5 (строка 108) и §11 всё ещё перечисляют Serper/Perplexity как поиск;
  в `decisions.md` (D-02/F-01) они исключены. Привести требования в соответствие через
  запись в `decisions.md` (по протоколу AGENT.md).
- `trend_velocity` есть в DDL `plan-m0.md:170`, но отсутствует в списке таблиц M0
  (`plan.md:39-41`) и в списке доменных моделей (шаг 3 `plan-m0.md`). Согласовать:
  либо добавить модель/таблицу в списки, либо пометить `trend_velocity` как «M2+» и
  вынести из DDL M0.
