## Цель и Definition of Done

Сделать систему **изучаемой**: новый человек по документам понимает, зачем она,
как устроен конвейер и — главное — **каким образом принимаются решения** (пороги,
цепочки проверок, интерпретация) и где лежат границы (дисклеймеры, не-цели).

**Приёмка:**

- `docs/methodology.md` объясняет: 6 фаз, agentic loop, верификационную цепочку, все
  пороги (зрелость D-06, on-chain D-07, pump D-08, анти-повтор, whale D-05), цитирование
  `[Ист](N)`, fail-closed/fail-open, ограничения.
- `docs/architecture.md` описывает модули, порты/адаптеры, схему SQLite, поток данных,
  конфиг (`topics`/`sources`/`onchain`).
- По документам можно: понять, как читать дайджест; добавить зону/источник/метрику.
- README и перекрёстные ссылки (AGENT.md/decisions.md/checklist.md) актуализированы.
- Каждый порог/решение имеет ссылку на ID решения (`D-xx`).

## Шаги (по порядку)

1. [ ] **`docs/methodology.md`.** Методика: конвейер, agentic loop, верификационная
   цепочка, пороги и почему они такие (со ссылками на `D-xx`), цитирование по каталогу,
   как формируются интерпретация и whale-маппинг, fail-closed/fail-open, ограничения.

2. [ ] **`docs/architecture.md`.** Гексагональная архитектура: модули
   (`domain`/`application`/`agent`/`adapters`/`api`), порты и адаптеры, схема SQLite
   (все таблицы), поток данных между фазами, расширение конфига.

3. [ ] **Руководство пользователя.** Как читать дайджест (§9), как запустить
   (CLI / `uv run` / `docker compose`), как добавить зону/источник/on-chain-метрику.

4. [ ] **Глоссарий.** Термины: зрелость, подтверждение/расхождение, pump, whale,
   novelty/анти-повтор, катализатор.

5. [ ] **Согласование ссылок.** Обновить README; перекрёстные ссылки между
   AGENT.md/decisions.md/checklist.md и новыми документами.

6. [ ] **Ревизия docstrings.** Привести docstrings кода к методике (единая терминология,
   ссылки на `D-xx` где уместно).

## Критерий готовности

Новый человек, не видевший проект, за один проход по `docs/` может объяснить: что
система делает, как устроен прогон, какие правила отсева/подтверждения применяются и
почему, и какие есть ограничения (не инвест. рекомендация, без ценовых таргетов).
