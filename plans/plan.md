## 0. Подход

Максимально переиспользуем проверенный скелет исходного решения (6-фазный конвейер,
агентный цикл, верификационная цепочка, SQLite-память, локальный bge-m3, сменный
LLM-шлюз). Крипто-специфику выносим в **два новых модуля** — on-chain-подтверждение
и whale-активность — и подключаем их поэтапно, а не с первого дня.

Принципы плана:
- **MVP-first**: сначала «работает вширь» (сбор → отбор → черновой отчёт), потом
  «работает вглубь» (верификация → on-chain → whale → интерпретация).
- **Конфиг, а не код**: зоны и источники живут в `config/`, а не в коде.
- **Измеримость с первого прогона**: eval-набор и метрики закладываем на M4, но
  разметку собираем с первого отчёта.

## 1. Фазы

| Фаза | Срок | Что делаем | Результат на выходе |
|------|------|------------|---------------------|
| M0. Каркас | нед. 1 | Python + FastAPI + SQLite WAL + локальный bge-m3 + OpenAI-совместимый шлюз; `topics.yaml` (10 зон) + `sources.yaml` (seed-каталог); ключи поисковых провайдеров | пустой конвейер запускается, веб-UI есть, зоны/источники настраиваются |
| M1. Сбор → отбор → черновой отчёт | нед. 2–3 | RSS + fetch_url + поисковый веер; эмбеддинг-фильтрация по зоне; кластеризация; сборка первого дайджеста без глубокой верификации | первый черновой еженедельный отчёт |
| M2. Исследование + верификация + память | нед. 3–5 | Agentic loop (fetch_url / search_web / on-chain-инструменты); верификационная цепочка с порогами; citation-by-number с сохранением номеров; анти-повтор и novelty-gate; подключение DefiLlama/CoinGecko | evidence-first отчёт, проверенные ссылки, анти-повтор |
| M3. Whale-модуль + инвестиционная интерпретация | нед. 5–7 | Whale Alert / биржевые потоки / smart money; маппинг на тренды; блок интерпретации + катализатор-календарь + freshness-декей | полный дайджест по структуре §9 требований |
| M4. Качество и эксплуатация | нед. 7–8+ | e2e-тесты, eval-набор (precision/recall), pump-фильтр, дисклеймеры, мониторинг стоимости/латентности | стабильный продакшн-режим |

### Детали по фазам

**M0. Каркас**
- Скелет: hexagonal layout (порты/адаптеры), frozen dataclass для доменных моделей.
- Схема SQLite: `trend_items` (сигналы + эмбеддинги), `reported_trends` (память),
  `evidence_bindings` / `evidence_verdicts`, `zone_run_results` (чекпоинты),
  `trend_candidates`, `search_ledger`, `report_runs`.
- LLM: DeepSeek напрямую (`deepseek-flash`), OpenAI-совместимый API; thinking off, `max_tokens` под задачу (D-02, D-15).
- Критерий готовности: конвейер прогоняется «вхолостую» на 1 зоне, данные пишутся в
  SQLite, веб-UI показывает статус.

**M1. Сбор → отбор → черновой отчёт**
- RSS через feedparser, fetch_url (LLM читает страницу), поисковый веер: Яндекс
  Search API v2 (RU) + EN через RSS/fetch_url (без ключей); Tavily free tier опц.
- Эмбеддинг-фильтрация (bge-m3) по зоне; дедупликация URL по нормализации.
- Кластеризация сигналов LLM; сборка дайджеста без верификации.
- Критерий готовности: стабильный недельный прогон по всем 10 зонам, отчёт читается
  человеком.

**M2. Исследование + верификация + память**
- Agentic loop (до N раундов), инструменты: fetch_url, search_web, `check_onchain`
  (TVL/объёмы/адреса), бюджет контекста (70% → форсаж финала).
- Верификационная цепочка: живость URL → дедуп → анти-повтор (косинус по эмбеддингам)
  → релевантность цитат → обоснованность прогноза → pump-фильтр.
- Цитата по номеру каталога `[Ист](N)`, URL подставляет код; номер сохраняется в
  финальном документе.
- Критерий готовности: все тренды имеют проверенные ссылки, повторы не переоткрываются.

**M3. Whale-модуль + инвестиционная интерпретация**
- Whale-фиды (Whale Alert и др.), биржевые притоки/оттоки, аккумуляция, smart money.
- Маппинг whale-активности на тренды как **подтверждение/расхождение** (не сигнал
  «повторить за китом»).
- Блок интерпретации (направление нарратива, горизонт, катализаторы, risk-флаги,
  статус on-chain-подтверждения) + дисклеймер.
- Катализатор-календарь + freshness-декей (дельта цены/TVL с первого сигнала).
- Критерий готовности: полный дайджест по §9 требований.

**M4. Качество и эксплуатация**
- e2e-тесты, eval-набор: золотой сет «слабый сигнал → тренд», precision/recall,
  ретроспективный false-positive (памп vs тренд через 2–4 недели).
- Pump-фильтр, дисклеймеры, мониторинг стоимости/латентности, алерты при массовом
  отказе провайдеров.

## 2. Ключевые технические решения

| Слой | Решение |
|------|---------|
| Язык/рантайм | Python 3.11+, менеджер пакетов uv |
| Архитектура | Гексагональная (порты/адаптеры), frozen dataclass для домена |
| LLM | DeepSeek напрямую (`deepseek-flash`), OpenAI-совместимый; thinking off (D-02, D-15) |
| Эмбеддинги | bge-m3 локально (кросс-язычный RU↔EN, 1024 dim) |
| Хранилище | SQLite (WAL) + numpy (вектора в Python); эмбеддинги BLOB float16; `sqlite-vec` опц.; Postgres — план «Б» при конкуренции (D-11) |
| On-chain (бесплатно) | DefiLlama (TVL/объёмы), CoinGecko (цены/эмиссия), Dune (запросы), Whale Alert API |
| On-chain (платно, опц.) | Nansen, Santiment, Glassnode, CryptoQuant — на M3+ |
| Поиск | Яндекс Search API v2 (RU) + EN через RSS/fetch_url (без ключей); Tavily free tier опц.; Serper/Perplexity — нет |
| API/UI | FastAPI (REST) + веб-интерфейс |
| Деплой | Docker / docker-compose |
| Тесты | pytest, black + isort |

## 4. Риски и митигация

| Риск | Митигация |
|------|-----------|
| X/Twitter — технически/юридически сложно скрейпить | курируемые списки, зеркала; приоритет — governance/форумы/GitHub/медиа |
| Whale-данные = шум, ложные сигналы | только как подтверждение тренда; агрегация по времени; не «follow the whale» |
| Пампы / заказные материалы | on-chain-подтверждение + ≥2 независимых источника + time-decay |
| Дата в крипте неоднозначна (твиты, governance) | timestamp из API/блока; fail-closed только где дата реально проверяема |
| Комплаенс (инвест. рекомендация) | дисклеймер, формулировки «направление нарратива», запрет ценовых таргетов |
| Стоимость | еженедельный каденс + лимит бюджета контекста (70% → форсаж финала) |
| Зависимость от платных API | старт на бесплатных tier; платные — только по необходимости на M3+ |

## 5. Метрики успеха и критерии готовности к разработке

- Precision/recall слабых сигналов на ручной разметке (золотой набор из первых отчётов).
- Доля трендов с on-chain-подтверждением vs «нарратив без денег» (цель — честная
  маркировка, не 100%).
- Ретроспективный false-positive: тренд, оказавшийся пампом (через 2–4 недели).
- Стоимость и время одного прогона.
- Субъективно: дайджест читается за 15–20 минут и помогает принимать решения.

## 6. Оценка усилий

- **Соло-разработчик с нуля (без кода оригинала):** 8–12 недель до полезного MVP
  (M0–M3), далее итерации по качеству.
- **При доступе к коду оригинала:** 3–4 недели (переиспользование конвейера, замена
  доменного слоя).
- Главная неопределённость — не техника, а **промпты фаз и качество on-chain/whale-
  интеграции**, поэтому M2–M3 закладываются с запасом.
